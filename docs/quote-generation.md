# Windows 可选自动补充台词

## 已确认的行为

- 默认关闭。开启前不调用模型；原额度查询仍为只读查询。
- 使用本机已登录的 Codex。模型下拉框通过官方 app-server 的 model/list 接口分页读取当前账号可用的文本模型，可刷新，也可沿用 CLI 默认模型；不等于所有 OpenAI API 模型，不承诺跟随桌面聊天模型。不提供 API key 或第三方模型接入。获取列表不会发起模型创作。
- 仅 Codex 窗口可见且挂件正在显示时启动补货。桌面模式也必须满足 Codex 可见。
- 未展示库存少于 20 句时，每批请求 43 句：G=7、P=16、T=20，合计 43。检查与去重后实际入库可能少于请求数。
- 默认每日最多 2 次任务，失败和取消也计数；至少间隔 30 分钟。三项数量、每日上限与间隔均可设置。
- 独立批次只使用人设、规则和台词样例；不读取聊天。以现有台词为样本归纳轻松吐槽、轻微傲娇、程序员/token 日常，穿插关心与鼓励。这不是 OpenAI 官方人设或作者发布的完整角色设定。
- 生成台词与原有语录分开保存；开启时优先使用未展示台词，耗尽时允许复用旧句。
- “编辑我的语录”区分常驻、生成和已删除列表。生成语录移入常驻后不再留在生成页，展示历史不清零；关闭生成功能后仍能出现。
- 常驻语录可设置 preferred，候选池内按原权重三倍抽取；未展示优先规则仍生效。可编辑文字、原权重、增加台词，或恢复内置模板。内置资源文件保持原样。
- 删除常驻或生成台词后保留可恢复的删除记录；规范化后相同的台词不会重新入库。常驻允许有意清空，不回退内置 33 句；无可用台词时气泡提示库存为空。
- 右键“立刻生成新语录”下方提示会消耗 token。默认忽略库存阈值、每日上限和调用间隔；每日任务和累计任务仍加一、最近调用时间更新，新增未展示台词计入库存（不修改阈值设置本身）。失败和取消也计任务，下一次自动补货仍受更新后的计数和间隔约束。
- 功能关闭、已有任务或手动请求待处理时，该按钮禁用；不排队多个任务。请求绑定设置版本且一分钟过期，关闭再启用不会复活旧请求。
- 从新版首次实际展示台词起本地记历史，关闭自动生成时也记录。无法还原旧版历史。
- 关闭时取消进行中的本地任务，停止后续任务；不会因重启、重新打开 Codex 或失败而自动开启。已经发出的远端请求可能已经消耗额度。
- 关闭后仅展示原有语录；保留生成库存和历史供再次开启使用。
- 首版 Windows UI；共享库存/调度模块可供以后 macOS 接入，但本次不启用 macOS 自动生成。

## 数据与维护

设置、生成台词、展示历史、每日/累计计数和语录管理记录存入用户数据目录，不覆盖用户的 quotes.json。默认规则随程序提供，用户修改保存在个人设置。

UI 是 quote-library.json 的唯一写者，用一个原子文件保存常驻列表和删除记录；worker 是 generated-quotes.json 与任务计数的唯一写者。生成文件保留原始归档，有效生成池扣除常驻和删除项。移动、删除、恢复不会和后台新台词互相覆盖。生成期间的改动在入库前再次读取、检查。已删除内容保存在本机以支持恢复。

累计任务字段升级时继承当前状态中已知的任务次数，之后持续累加，不能还原旧版未保存的历史总数。

首次排版先用一次全文选区计算候选分数，再对高分候选构建字形轮廓并执行原来的椭圆包含检查；C# helper 在启动时编译。相同字体和文字继续使用缓存。隔离实测表明未缓存的新台词排版明显加快；这不表示所有原生点击延迟都已定位或消除。

开发使用独立 Git 分支；现有更新器拒绝整包替换 Git 源码目录。正式安装包内改动会被上游 Release 覆盖。提交 PR、合并与正式发版是不同阶段，只有包含此功能的发布包才能随官方更新带入此功能。
